# Systematic Coding

## Before Coding

Fetch and review: memory (preferences, phrases, observations), codebook (density, overlap policy), codes (inclusion/exclusion, examples). Codebook is source of truth.

## Core Principles

Comprehensive coverage. Code every instance—repetition is data. Flexible granularity (phrase/sentence/paragraph). Follow codebook density setting.

## Content Type Adaptations

**Interviews:** Speakers, turn-taking, question-response dynamics. Each turn fresh unit.
**Official docs:** Formal language, institutional voice, hedging matters.
**Field notes:** Observation vs interpretation. Researcher voice is data.
**Media:** Framing devices, attribution, who speaks/who's spoken about.
**Digital:** Informal register, threading, temporal dynamics.

## Three-Phase Protocol

**Phase 1: Discovery (Blind Pass)**

Mental frame: "I'm seeing this text for the first time. What's here?"

Work through file sequentially. Code what is explicit, obvious, surface-level. Focus on:
- Direct statements, clear attributions
- Explicitly stated themes
- Obvious structural elements

For unclear instances:
- Don't ask immediately
- Mark medium/low confidence
- Collect questions across entire file

After file complete: present all collected questions in one batch.

**Example questions to collect:**
- "'Oh, wonderful timing as always' — is that sarcastic or genuine?"
- "'I have full confidence in the process' — code the literal statement or the implied skepticism?"
- "Two passages could fit either defensive or uncertainty. Which takes priority when both apply?"
- "This passage is only a few words but with surrounding context seems significant. Code it?"

**User Q&A Interlude**
Researcher answers aggregated questions. Store clarifications for Phase 2.

**Phase 2: Synthesis (Informed Pass)**

Mental frame: "Now that I know what this file contains and have the researcher's guidance, what did I miss?"

This is a different cognitive task. Phase 1 was discovery ("what's here?"). Phase 2 is synthesis ("what patterns emerge with full context?").

Work through file again applying:
- User's clarifications about ambiguous instances
- Patterns you noticed across the full file
- What you now know about how the file develops

Revisit early sections. What looks different now? Catch pervading patterns missed initially.

**Phase 3: Reflection (Post-Coding Questions)**

Mental frame: "Challenge what you coded."

Before marking complete, ask researcher questions that might add or remove codes:
- Meta-patterns across document? (overall tone: defensive, apologetic, technical)
- Absences? (what's NOT said? avoided topics?)
- Higher-level themes emerging from codes applied?
- Overcoded anything? (applied where doesn't fit)
- Inconsistent application? (coded here but not there)
- Mis-applied instances in specific category?

## Repetition is Data

The frequency and distribution of codes IS the analysis.

If a theme appears 50 times, code it 50 times. That's not redundancy—that's data.

**This is NOT summarization:**
- ❌ "Economic justification appears in the document"
- ✓ Code economic justification 47 times across 12 sections

Don't stop at first occurrence. Every instance matters. Frequency reveals emphasis, distribution reveals patterns.

## Common Gaps

Patterns that tend to get undercoded:

- **Hedging phrases** — "at this time," "currently," "for now" get skipped because they're subtle. Code each instance.
- **Weak formulations** — Don't skip early/weak versions because a stronger one exists later. Both are data.
- **Opening statements** — First sentences often frame what follows but get overlooked in favor of "main content."
- **Sandwiched content** — Codeable content between two coded segments gets missed. Scan gaps.
- **Multi-code eligibility** — One segment can fit multiple codes. Don't stop at first match.
- **End-of-section fatigue** — Attention drops. Re-scan final portions.
- **Turn boundaries** — In dialogue, each speaker turn is fresh. Don't assume continuation of previous turn's codes.

## Sparse vs Dense Coding

Follow the codebook's density preference. Same passage coded differently:

**Source text:**
> "At this point in time, we believe the situation is under control. Our experts have advised us that the measures are sufficient. We trust that everyone will act responsibly."

**Sparse coding (1 code):**
- Only "act responsibly" → responsibilization

**Dense coding (5 codes):**
- "At this point in time" → temporal-hedge
- "we believe the situation is under control" → public-commitment
- "Our experts have advised us" → appeal-to-authority
- "the measures are sufficient" → policy-commitment
- "everyone will act responsibly" → responsibilization

Check the codebook's density setting and code accordingly.

## Phase 2 Checklist

Opening statements coded? Gaps between segments? Final sections? Each turn fresh? Multi-code check? Every instance?

## Workflow

1. Fetch memory, codebook, codes
2. Sync `get_project_changelog`
3. Phase 1: Code explicitly, collect questions
4. User Q&A: researcher answers, store clarifications
5. Sync `get_project_changelog`
6. Phase 2: Code with full context + clarifications
7. Phase 3: Ask about meta-patterns, absences, consistency, overcoding
8. Use `batch_create_codes` for 2+ new codes
9. Update memory with patterns/preferences
10. Summarize for researcher

## Completion Summary

After each file, report to researcher:
- Coverage (segments coded)
- Code distribution (which codes appeared, how often)
- Key patterns observed
- Anything skipped or uncertain
- Framework issues to revisit (missing codes, unclear boundaries)
- Cross-file patterns emerging

Update memory with observations.

Then STOP. Wait for researcher review before continuing to next file. Don't auto-loop through multiple files.
